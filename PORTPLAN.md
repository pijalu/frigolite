## 1. Mission

Frigolite is a pure-Go reimplementation of SQLite that reads/writes standard
`.db` files. The goal of this plan is to make **all applicable** SQLite TCL
tests pass, driven by the `testgen/` packages generated by the `tools/tcl2go/`
transpiler. Where a test fails, the **first** action is always to decide
whether it is an engine bug or a transpiler bug — by writing a pure-Go test
that exercises the engine directly and comparing against the `sqlite3` oracle.

The plan is **top-down by feature value**: full CRUD correctness before query
features before schema/constraints before functions before advanced SQL. FTS,
WAL, and other heavy subsystems come last.

### How tests are wired
- **testgen/** — 614 Go test packages, each generated from one SQLite `.test`
  file by `tools/tcl2go/`. Build tag `testgen` (opt-in). Run with
  `go test -tags testgen ./testgen/<pkg>/ -count=1`. **One package = one goal.**
- **testdata/*.json** — 1003 JSON harness cases (older, secondary signal).
  Driven by `frigolite_harness_test.go`; excluded/slow sets in
  `slowTestFiles` / `unsupportedTestFiles` maps there.
- **Root `*_test.go`** — hand-written unit tests. Pre-test files named
  `frigolite_p<N>_*.go` isolate features before touching TCL tests.

### Where the code lives
- `internal/sql/` — hand-written lexer (`lexer.go`) + AST (`ast.go`).
- `internal/parse/` — **lemon-generated LALR parser**. Reduce handlers are
  rule-numbered (`handleRule(ruleNo, ...)`). Grammar source is the SQLite
  `parse.y`; rules are referenced by number.
- `internal/exec/` — query engine: `select.go`, `insert.go`, `update.go`,
  `delete.go`, `ddl.go`, `alter.go`, `pragma.go`, `expression.go`, `engine.go`.
- `internal/btree/`, `internal/pager/`, `internal/storage/` — file format,
  page cache, B+Tree.
- `internal/function/` — scalar + aggregate functions.
- `internal/schema/`, `internal/rename/`, `internal/vtab/`, `internal/fts/`,
  `internal/value/`, `internal/util/`, `internal/auth/`.

## 4. Phasing (execution order)

Each phase is a set of **independent goals**. Within a phase, goals may run in
parallel where they don't touch the same files; otherwise serialize. Every goal
runs with **`freshContext: true`** and carries state only via its **handover
note**.

```
G0  FOUNDATION          grammar completion + triage harness + oracle helper
└─ G1  CRUD CORE         (THE critical path)
   ├─ G1.CREATE   G1.INSERT   G1.SELECT
   ├─ G1.WHERE    G1.UPDATE   G1.DELETE
   ├─ G1.TYPES    G1.EXPR
   └─ G2  QUERY FEATURES  (depends on G1 stability)
      ├─ G2.JOIN  G2.SUBQUERY  G2.AGGREGATE
      ├─ G2.ORDERBY  G2.SETOPS  G2.VIEW
      └─ G3  SCHEMA & CONSTRAINTS
         ├─ G3.ALTER  G3.INDEX  G3.TRIGGER
         ├─ G3.FKEY  G3.CONSTRAINTS  G3.COLLATE
         └─ G4  FUNCTIONS
            ├─ G4.STRING  G4.DATETIME  G4.NUMERIC  G4.PRINTF
            └─ G5  ADVANCED
               ├─ G5.PRAGMA  G5.ATTACH  G5.VTAB  G5.EXPLAIN  G5.ANALYZE
               └─ G6  TRIAGE / N-A / DEFERRED finalization
```

**Dependency rule:** a later phase must not start until its predecessor phase's
*core* goals are green (its verify command passes). Fix-forward regressions
immediately — a later goal that breaks an earlier goal's verify command is a
**blocker**, not a to-do.

## 6. Definition of Done (per task)

A task is **done** when **all** are true:
1. Its verify command passes (`go test` exit 0) on the listed testgen packages.
2. Its hand-written pre-test file passes (`go test -run TestP<N>... .`).
3. `go build ./...` passes.
4. `make quality` passes (vet, staticcheck, gocyclo ≤20, gocognit ≤30).
5. No new regression in any *earlier* task's verify command.
6. Every failure that was *actually* an N/A package is documented in
   `plans/NOT_APPLICABLE.md` + the harness map, not papered over.
7. Each fix was verified against the `sqlite3` oracle (expected output recorded
   in the commit message or pre-test), and every engine-vs-transpiler decision
   was made via a pure-Go test **first**.
8. Commits follow the cadence in §7 and the task's own step list; the plan
   checkbox is updated + committed.

## 7. Commit & Cadence Rules

- **Small, atomic commits** — one logical fix per commit, message prefixed
  `G<N>.<TASK>.<step>: <summary>` (e.g. `G1.UPDATE.2: propagate WHERE eval errors`).
- After each engine fix, re-run the **task's** verify command before committing.
- After a transpiler fix in `tools/tcl2go/`, regenerate with
  `go run ./tools/tcl2go/`, review `git diff` blast radius (it regenerates
  ~all testgen files), and commit regenerated files separately:
  `G<N>.<TASK>.<step>: regenerate testgen after <reason>`.
- **Never** weaken, skip, or hard-code a test to make it green. If a generated
  assertion is wrong, fix the transpiler — do not edit generated files by hand.
- Update the task MD's checkbox state in the same commit that closes a step.

---

## 8. Oracle & Triage Helpers

- **Oracle:** `/usr/bin/sqlite3` — derive expected output, error text, and edge
  cases. Record the exact invocation in pre-tests/commit messages.
- **Triage rule (mandatory):** on any testgen failure, write a **pure-Go test**
  driving the engine via `frigolite.Open/Exec/Query` that exercises the failing
  feature. Run it:
  - If it **fails** → engine bug → fix the engine, re-run both tests.
  - If it **passes** while the testgen test fails → transpiler bug → fix
    `tools/tcl2go/` and regenerate.
  - See `portplan/GUIDELINES.md §Triage` for the full protocol.

---

## 9. Regressions & Scheduling

- Run a goal with **`freshContext: true`**. The handover note is the *only*
  state that crosses goals — keep it accurate (State / Decisions / Next / Risks
  / Carried limits). Max 4096 chars.
- Each task's verify command is deliberately **narrow** (its packages + pre-test
  + build). Do **not** run all 614 packages on every commit — that is slow and
  noisy. Run a broader regression sweep only at phase boundaries.
- A goal that breaks an earlier phase's verify command is **blocked**, not
  deferred; fix before proceeding.

## 10. Out of Scope (explicit)

- **WAL mode / shared-memory concurrency** — 33 packages, deferred (see
  `plans/DEFERRED.md`). Requires a new journaling + locking architecture.
- **FTS3/4/5** — full-text search engine not implemented (shadow tables). N/A.
- **RTree, JSON1, session, RBU, zipfile** — extension subsystems. N/A.
- **C API surface** (`sqlite3_prepare`, `sqlite3_step`, …) — pure Go, no C API.
  Map C-API test patterns to a Go paradigm inside the transpiler/runtime.
- **Fault injection / OOM / corruption / custom VFS** — test SQLite C internals.
  N/A; document, don't port.
