> **Triage rule**: On testgen failure, write a **pure-Go test** via
> `frigolite.Open/Exec/Query` first. Fails → engine bug. Passes while testgen
> fails → transpiler bug (`tools/tcl2go/`).


> **SOURCE FIRST (mandatory)**: SQLite's approach always wins. Before fixing any
> engine gap, read the actual SQLite source at `/Users/muaddib/dev/sqlite`
> (`src/*.c`, `ext/misc/`, `test/`). The oracle (`/usr/bin/sqlite3`) tells you
> WHAT; the source tells you WHY and HOW. Implement faithfully from the C
> source, then verify against the oracle.
> A gap should always be fixed correctly - faithfully from the C source -
> even if important work is required. Use goals (this plan, the goal tool) to
> plan/replan based on a detailed analysis and plan, never piecemeal hacks.

> **NO TRY/FAIL (mandatory)**: Do not waste time try/failing - step back, clean
> up, review the SQLite source, then write a detailed plan and execute. When
> the work deviates (perf problems, unexpected failures), stop, revert/clean
> the exploratory edits, re-read the relevant SQLite source
> (`/Users/muaddib/dev/sqlite`), produce a written plan (what/why/exact
> files/ordered steps/verify), and only then execute. Do this in a clean
> pre-goal state: no half-applied experiment in the working tree when
> planning.
