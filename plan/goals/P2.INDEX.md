## Status (P2.INDEX execution)

### DONE — all 4 packages un-skipped and green

Four engine fixes (all verified against pure-Go repro tests and `/usr/bin/sqlite3`):

1. **CREATE INDEX collation validation** (`internal/execddl/ddl_index.go`):
   SQLite resolves COLLATE names in index key expressions and the partial-index
   WHERE clause at CREATE INDEX compile time. The engine previously only checked
   index columns' declared collations and ran that check *after* the schema entry
   was written (leaking a partial index on error). Now `validateIndexCollations`
   runs before the root page allocation and also walks the key terms + WHERE for
   explicit COLLATE operators (`no such collation sequence: g`).
   - Fixed: indexA-5.1, indexA-5.2 (was: index leaked, then "index ex1 already exists")
   - Also fixed harness: collate3-1.3, temptrigger 8.1.1/8.2.3/8.3.1

2. **INDEXED BY partial-index predicate match** (`internal/execddl/ddl_drop.go`):
   `whereImplies` compared the stored predicate text (`b='abc' AND i=5`) against
   the AST rendering (`b = 'abc' AND i = 5`); the spacing mismatch broke
   `SELECT * FROM t1 INDEXED BY i1 WHERE b='abc' AND i=5` → spurious
   "no query solution". `normalizeSQLText` now removes ALL whitespace from both
   sides. Fixed: indexA-7.0.

3. **PRAGMA integrity_check / quick_check expression index keys**
   (`internal/exec/pragma_quickcheck.go`): `indexKeyForRow` only resolved plain
   column names; expression keys (`substr(b,2,4) COLLATE rtrim`, `abs(d)`) fell
   through to an empty key, so every row collided → false
   "non-unique entry in index X". The quickcheck now evaluates expression keys
   against the row (same path as index maintenance) and unwraps COLLATE wrappers.
   Fixed: indexexpr1-800/820, indexexpr1-900, indexexpr1-1610, pragma4-4.2.4.

4. **JSON1 core json_extract/json_insert** (`internal/function/json.go`,
   registered in `internal/function/function.go`): indexexpr3 defers to the JSON
   extension, whose core was landed here so expression indexes over
   `json_extract(j,'$.x')` evaluate per row at CREATE INDEX time (test 1.0) and
   the EQP tests 2.1-2.5 run. The relaxed-mode parser (unquoted keys,
   single-quoted strings, trailing commas, hex/+/./NaN/Infinity), path walker,
   and serializer match SQLite's json.c (number text preservation, %.15g reals,
   JSON escaping). Both functions registered Innocuous so they are SchemaSafe
   for CREATE INDEX. Verified against `/usr/bin/sqlite3` on all indexexpr3
   inputs (json_extract('{x:"one"}','$.x')→'one', json_insert('{}','$.y','two')
   →'{"y":"two"}') and 45+ oracle-derived cases in `frigolite_json_test.go`.
   Fixed: indexexpr3 (un-skipped, real test body).
