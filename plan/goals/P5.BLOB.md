## Tranche 3 fix plan — `incrcorrupt` (source-first analysis done)

Failure inventory (all 18 assertions): (a) `page_count` 22 vs 24 in both
1.0/2.1; (b) `SQLITE_OK`/`not an error` vs `SQLITE_CORRUPT`/`database disk
image is malformed` in 1.4-1.17 / 2.4-2.17.

Root causes (SQLite source: `src/btree.c` `sqlite3BtreeIncrVacuum` /
`lockBtree`, `src/pager.c` `sqlite3PagerSharedLock`):

1. **Transpiler drops the corruption commands**: `db_save`, `hexio_write`,
   `chan truncate` are emitted as comments → corruption never applied →
   SQLITE_CORRUPT unreachable. Fix `tools/tcl2go`: implement `hexio_write`
   (hex-decoded WriteAt), `db_save`/`db_restore` (test.db* ↔ sv_test.db*
   copies), `chan truncate $fd N` (fd var holds filename → os.Truncate).
2. **`sqlite3_errcode` mapping**: `DB.errorCode` lacks malformed→
   SQLITE_CORRUPT; `stmt.go` Step hardcodes SQLITE_ERROR; transpiled
   `SetLastErr(msg, "SQLITE_ERROR")` clobbers. Fix: export
   `DB.ErrorCodeFor(err)` (malformed→SQLITE_CORRUPT), use it in stmt.go and
   in the transpiled SetLastErr line (`processsqlite3.go:352`).
3. **page_count parity (22 vs 24)**: oracle layout = header(1) + ptrmap(2) +
   t1 root(3) + sqlite_autoindex root(4) + 20 leaves(5-24). Our layout has
   identical leaf packing (verified hexdump: 1 cell/page) but lacks (i) the
   ptrmap page and (ii) a physical root page for `sqlite_autoindex_t1_1`
   (schema entry exists, rootpage=0). Fix: pager/btree allocate ptrmap page
   at PTRMAP_PAGENO positions when auto_vacuum is on (btree.c
   `allocateBtreePage` auto-vacuum branch), and allocate a physical empty
   index-leaf root for autoindex entries (ddl `createAutoIndexes`).
4. **auto_vacuum mode mapping inverted** (`pragma_state.go` AutoVacuum):
   SQLite `getAutoVacuum` (pragma.c): none=0, **full=1, incremental=2**;
   engine had full=2/incremental=1. Also persist mode in header (largest
   root page field @52 nonzero ⇒ autoVacuum; incremental-vacuum flag @64
   nonzero ⇒ incremental; btree.c lockBtree reads both) so a fresh
   connection observes it.
5. **`PRAGMA incremental_vacuum`** must exist and follow btree.c
   `sqlite3BtreeIncrVacuum`: `nFree = get4byte(hdr[36])`; if
   `nOrig < nFin || nFree >= nOrig` → SQLITE_CORRUPT (this is test 1.x:
   hexio_write @36 sets freelist count 25 > 24 pages); else no-op DONE when
   freelist empty (test 1.1 → {}). Also `PRAGMA auto_vacuum=…` on a
   corrupt db must fail (lockBtree per-statement check below).
6. **Per-statement external-change detection (test 2.x)**: SQLite
   `sqlite3PagerSharedLock` runs at every statement start (page 1 is
   released between autocommit statements): compares **16 bytes @24**
   (dbFileVers — includes freelist count @36) → `pager_reset` on change;
   then `pagerPagecount` (file size) and `lockBtree` rejects
   `nPage(header@28) > nPageFile` → SQLITE_CORRUPT (test 2.x: truncated
   file). Engine: extend `schema.Manager` external-mod tracking to MAIN
   (own commits refresh baseline), compare the 16-byte vers + file size,
   invalidate pager cache + revalidate header (freelist/root checks) per
   statement.

Order: (1)+(2) transpiler+errcode [independent, unblocks corruption
application]; (3)+(4) parity+mode [page_count]; (5)+(6) pragma+per-stmt
checks [SQLITE_CORRUPT]. Pure-Go regression tests per slice; oracle checks
with /usr/bin/sqlite3 (page_size=1024).
