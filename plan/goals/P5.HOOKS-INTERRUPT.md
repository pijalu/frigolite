## 2. Engine design (pure Go)

### 2.1 Countdown state — `internal/exec/engine.go`
Add `interruptCount int` next to `progressState`. New methods on Engine:
`SetInterruptCount(n)`, `InterruptCount() int`. Extend `checkProgress()`
(prepend, before progress-callback logic):
```go
if e.interruptCount > 0 {
    e.interruptCount--
    if e.interruptCount == 0 {
        e.interrupted = true
        return fmt.Errorf("interrupted")
    }
}
if e.interrupted { return fmt.Errorf("interrupted") } // stays failing until consumed
```
Fast path first (hot loops): `if cb==nil && count==0 && !interrupted {return nil}`.
Deterministic: pure op counting, no time dependence → 4.x loop-bound works.

### 2.2 Statement-entry interrupt must force tx rollback — `internal/exec/engine_core.go`
Today `Exec()` (~line 645) early-returns `interrupted` BEFORE the isDML/rollback
classification at ~1090. interrupt-3.x requires an interrupted in-tx INSERT to
roll back the whole tx (temp schema reset included). Fix: route entry-interrupt
through the same `forceTxRollback` classification (set result, skip execution,
fall into shared error handling) instead of early return.

### 2.3 Wire `ctx.CheckProgress()` into row loops
Interface already declared in `internal/execquery/context.go:92`,
`internal/execdml/context.go:69`, `internal/execddl/context.go:43` — only
`select_cte_exec.go:402` calls it today. Add per-row/per-item calls at:
- `internal/execquery/select_scan.go` `scanTableRows` (~347) row loop
- `internal/execquery/select_agg.go` group/aggregate loops
- `internal/execquery/select_join.go` nested-loop iterations
- `internal/execquery/select_setop.go`, `window.go`, order-by sort loop
- `internal/execdml` INSERT…SELECT / UPDATE / DELETE row loops
- `internal/execddl/ddl_index.go` index build loop; `ddl_drop.go` entry ops
- VACUUM: locate the stmt dispatch handling `*sql.VacuumStmt` (grep in exec;
  currently silent) — add ≥1 progress check per page/table copied; abort leaves
  original file intact (atomic rebuild: write to temp, swap at end).

### 2.4 DDL atomicity (1.2 cksum)
Countdown check fires before mutation for single-op DDL (DROP/CREATE); for
multi-entry DDL ensure checks precede each mutation batch or snapshot-rollback
mirrors DML pager snapshots. cksum equality is the gate.

### 2.5 Public API — `frigolite.go`
`SetInterruptCount(n int)`, `InterruptCount() int`, `LastErrCode() string`
(engine passthrough). errcode path already maps `interrupted`→
`SQLITE_INTERRUPT` (`frigolite.go:691 errorCode`) and Exec/Query record it —
no change needed there.

### 2.6 VACUUM compaction (2.4) — decision
Implementing real compaction (rewrite live pages, shrink file) is a pager
project; defer. Pattern-skip `interrupt-2.4` in `skiptests2.go` with evidence
"VACUUM file-shrink not implemented (same class as e_vacuum file-size skips)";
note in PORTPLAN. 2.2/2.3 (interruptibility + content invariance) still real.

## 6. Risks

- **Op-count determinism** across identical runs — required for 4.x loop bound;
  pure counting guarantees it (no clock/random in checkProgress).
- **Loop termination** in 1.2/2.2: every statement must consume ≥1 op and
  complete when countdown exceeds ops — ensure at least one checkProgress per
  statement even for trivial DDL (place check at statement start inside Exec).
- **Perf**: hot-loop guard (2.1 fast path) keeps zero-cost when disabled.
- **DDL partial state** on mid-statement interrupt (1.2 cksum gate catches).
- **`interrupt-4` iteration volume**: max_count could be large; cap test runtime
  acceptable (t1 is 64 rows; query ops bounded, loop ~hundreds — fine).
