### Engine (frigolite.go / frigolite_backup.go)

- `Exec`/`Query` set the connection's last-error state on failure and clear it
  on success (sqlite3_errcode / sqlite3_errmsg emulation).
- `errorCode()` maps engine errors to SQLITE_* result-code strings
  (INTERRUPT/SCHEMA/BUSY/CANTOPEN/MISUSE/NOMEM/ERROR).
- `LastErr()` returns "not an error" when no error is recorded (SQLite's
  sqlite3_errmsg semantics).
- Public `SetLastErr(msg, code)` for the transpiler's connection-state
  emulation.

### Transpiler (tools/tcl2go)

- `sqlite3_prepare` executes a prepared query at prepare time (via db.Query on
  the first statement) so compile-time errors (bad column/table name) set the
  connection error state (capi3-1.7/1.8.x/1.9).
- `sqlite3_prepare` TAIL argument: predeclared at function scope
  (collectPrepareTailVars) and assigned via `tclSqlTail`; set-var bodies that
  read a tail variable compare whitespace-collapsed (capi2-2.1/2.5).
- `sqlite3_close`: SQLITE_BUSY when the main connection has unfinalized
  prepared statements; SQLITE_MISUSE on double-close; SQLITE_OK for a
  failed-open connection. `sqlite3_errmsg`/`errcode` handle failed-open and
  closed connection states (capi3-3.x, capi3c-3.x).
- `sqlite3_next_stmt` → "" (statement registry not modeled; capi3d loop fix).
- `stepsql` command substitution → "0" (result code; capi2-7.12).
- `[clang_sanitize_address]` → "0" (harness global; enables the
  `==0 && 0` dead-condition guards).
