### Root cause — fts4lastrowid (investigated, NOT fixed — handover evidence)

Symptoms: `INSERT INTO t1 VALUES('one')` → `r.LastInsertRowID=0` AND
`db.LastInsertRowID()=0`. Test expects 1/3/6/-22/10/14.

Confirmed facts:
- `insertFTSRow` (internal/execdml/insert_exec.go) DOES call
  `e.ctx.SetLastRowID(nextRowID)` (line ~448) and returns
  `&Result{Changes:1, LastInsertRowID: nextRowID}`. Debug print confirmed
  nextRowID=1 at that point.
- `writeFTSDocsizeRow`/`writeTableRow` return **nil on success** — the earlier
  hypothesis (docsize Result short-circuit) is WRONG. Do NOT chase it.
- `execInsertTuples` (insert_exec.go) aggregated only Changes/InsertedChanges,
  DROPPING LastInsertRowID from the per-row insert results → outer Result
  LRI=0. A fix `return &Result{..., LastInsertRowID: e.ctx.LastRowID()}` makes
  the **Result field** correct (probe showed LRI=1) BUT `db.LastInsertRowID()`
  (engine e.lastRowID) still returns 0 after the statement.
- Therefore the REAL bug: e.lastRowID is RESET to 0 somewhere AFTER
  execInsertTuples but before the statement returns. Suspects (unverified):
  (a) the autocommit FTS flush (execFlushAutocommit → FlushFTSSegments →
  nested `e.ctx.Exec` shadow-table INSERTs) — a nested Exec's
  execTrackChanges/insert path may SetLastRowID(0) or return a result with
  LRI=0 that overwrites; (b) execTrackChanges guard `if res.LastInsertRowID >
  0` (engine_core.go:1067) DROPS negative rowids (-22) from the Result field
  — must be `!= 0` to match SQLite.
- SQLite reference: fts3_write.c sqlite3Fts3UpdateMethod sets *pRowid to the
  FTS docid; the VDBE OP_Insert stores it as db->lastRowid (so every FTS
  insert updates last_insert_rowid, incl. negative docids).

Suggested next step (NO TRY/FAIL): instrument Exec (engine_core.go) — print
e.lastRowID after execDispatch, after execTrackChanges, and after
execFlushAutocommit for a single FTS INSERT. Identify which step zeroes it.
Then fix the reset (likely the flush's nested exec or a Snapshot/rollback
path). Also change the `>0` guard to `!=0` for negative-rowid support
(oracle: INSERT rowid=-22 → last_insert_rowid()=-22).
