# P6.FTS5 — `fts5` virtual table (no NoopModule)

## Objective
Implement the SQLite `fts5` virtual table module in frigolite so `fts5` is no
longer registered as `NoopModule`. fts5 is a complete full-text engine
(src/fts5.c + ext/fts5/) with its own tokenizers, inverted index, query
language (AND/OR/NEAR/NOT/"..."/colspec), aux functions (`fts5`, `bm25`,
`highlight`, `snippet`, `porter`, `trigram`), and shadow tables.

## Context
- `internal/vtab/vtab.go` registers `fts5` as `&NoopModule{}` (line ~117). There
  is **no** fts5 code anywhere in the tree (grep-confirmed). `internal/fts/`
  contains FTS3/4 only (`NewFTS3Module`, `NewFTS4AuxModule`, tokenizers
  simple/unicode61). The `fts3`/`fts4`/`fts4aux` Noop registrations are a
  **wiring gap** — the real `internal/fts` modules already exist and simply
  need to be registered (corrected in this same effort).
- Depends on the **`vtab.Database` interface** (slice 1 of P6.RTREE) for shadow
  tables (`%_data`, `%_idx`, `%_docsize`, `%_config`) and function registration.
- Source of truth: `../sqlite/src/fts5.c`, `../sqlite/ext/fts5/*`; oracle
  `/usr/bin/sqlite3`.

## Design (SOLID, phased)
- `internal/fts5/` package — mirrors SQLite's fts5 structure but Go-idiomatic:
  - `fts5_index.go` — inverted index over shadow tables, doclist/position lists.
  - `fts5_tokenize.go` — unicode61 + ascii tokenizers (reuse existing tokenizer
    infra from `internal/fts/tokenizer.go` where compatible).
  - `fts5_query.go` — phrase/NEAR/NOT/colspec parser + evaluator.
  - `fts5_func.go` — `bm25`, `highlight`, `snippet`, `porter`, `trigram`,
    `fts5` aux.
  - `fts5_module.go` — `FTS5Module`, xCreate/xConnect, schema, shadow tables.
- Reuse `internal/function` for aggregate/scalar registration via `vtab.Database`.

## Slices (this is a large, multi-session module — scope acknowledged)
1. Wire `fts3`/`fts4`/`fts4aux`: register the existing `internal/fts` modules in
   `RegisterDefaults` (remove their Noop aliases). Verify fts3/4 tests green.
2. fts5 skeleton: `NewFTS5Module(db)`, shadow table creation, schema, empty
   INSERT/SELECT. Remove `fts5` Noop.
3. Tokenizers + index write (INSERT/MATCH single-term). Verify vs oracle.
4. Query language (AND/OR/NEAR/NOT/phrase/colspec). Verify vs oracle.
5. Aux functions (bm25/highlight/snippet/porter). Verify vs oracle.
6. Tests: `go run ./tools/tcl2go/ fts5` + fts3/4 suites; oracle transcripts
   under `.agents/fts5_oracle/`.

## Gates
- `tools/quality_gate.sh` on changed files; `go test -run TestSOLID_` green.
- Pure-Go pre-test + oracle before testgen.
- Final verify per package (fts3/fts4/fts5 suites).
