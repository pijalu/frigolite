## Session 12: t14 DECISION — introspection modules superseded via native Go ports

The 3 remaining RED packages depend on two C-API/planner-introspection modules
that frigolite's architecture does not expose:

- **stmtvtab1** → `sqlite_stmt` (ext/misc/stmt.c, SQLITE_ENABLE_STMTVTAB):
  an eponymous vtab over the connection's **linked list of live Vdbe
  statements**, reporting per-statement C `sqlite3_stmt_status()` counters
  (nscan/nsort/naidx/nstep/reprep/run/mem), `sqlite3_stmt_busy()`,
  `sqlite3_stmt_readonly()`, `sqlite3_column_count()`. frigolite has no C
  statement cache / Vdbe register machine / per-stmt memused accounting.
- **vtabdistinct, vtabrhs1** → `qpvtab` (ext/misc/qpvtab.c): a test/debug vtab
  whose xBestIndex **echoes the raw C `sqlite3_index_info`** (nConstraint,
  per-constraint column/op/usable, nOrderBy, idxFlags, colUsed) and calls
  **`sqlite3_vtab_rhs_value()`** (planner RHS extraction, SQLITE_NOTFOUND for
  non-constant/function/?N RHS) and **`sqlite3_vtab_distinct()`** (planner
  DISTINCT/ORDER-BY/GROUP-BY return-set classification). frigolite's vtab
  contract is a constraint-sink BestIndex (SetHiddenConstraint /
  PushSpellfixConstraint / PushRTreeConstraint / SetMatchConstraint), not the
  mutable C index_info struct; these planner internals are not plumbed out.

Both are **test-only debugging hooks** with no user-facing feature value.
Faithfully porting them means reproducing the C prepared-statement lifecycle
and the C query-planner index_info surface in Go — a large architectural
change strictly to satisfy introspection tests, not a database capability.

**Decision (user-approved, 2026-05): supersede all 3 via the Pure-Go
supersession policy** (AGENTS.md). Each gets a `frigolite_<name>_test.go`
native port that documents the superseded C contract and pins the engine-gap
boundary (asserting the engine rejects the unknown module with "no such
module"/"no such table"), rather than fabricating C-planner internals the
engine does not have. This is the same treatment as swarmvtab{,2,3}
(Session 10). The TCL testgen packages are listed in
`tools/tcl2go/skiptestfiles.go` + `frigolite_harness_test.go` pointing at the
native ports.

Outcome: all 30 target packages accounted for — 24 passing natively as
testgen, 3 (swarmvtab*) + 3 (stmtvtab1, vtabdistinct, vtabrhs1) = 6 superseded
by native Go ports.
