## Resolution

The WAL write/recovery subsystem is **implemented in the engine** (previously a
stub). The 7 TCL testgen packages are **SUPERSEDED** by pure-Go native tests in
`frigolite_walrecovery_test.go` — they are not N-A. Per the supersession policy,
a TCL package may be skipped only when a native test covers the same functional
contract AND the transpiler genuinely cannot emit it. Both hold here:

- **Engine WAL path implemented** (the WAL-A/B "G7 subsystem" gap is closed for
  the crash-recovery / wal_hook / fault contract):
  - `internal/pager/wal.go` — `-wal` writer with SQLite-compatible fibonacci
    checksums, commit frame with post-transaction DB size, wal-index `-shm`
    materialization, frame-commit recovery (`wal.c walIndexRecover`), and
    RESTART-style checkpoint.
  - `internal/pager/pager.go` — `SetJournalMode("wal")`, `JournalMode`,
    `SetWalHook`, `SetWalFault`, `Checkpoint`, `WalFileSize`; `Open` auto-detects
    a WAL database from the `-wal` file and recovers committed frames;
    `InvalidateCache` rebuilds the cache from the WAL.
  - `internal/execpragma/execpragma.go` + `internal/exec/pragma_state.go` —
    `PRAGMA journal_mode=WAL` (routes commits through the WAL) and
    `PRAGMA wal_checkpoint` (RESTART) wired end-to-end.
  - `frigolite.go` / `internal/exec/hooks.go` — `DB.SetWalHook`
    (`sqlite3_wal_hook` C-API equivalent).
- **Native contract tests** (`frigolite_walrecovery_test.go`) cover the same
  behavior the TCL suites assert:
  - `TestWalCrashRecoveryEngine` ⇄ walcrash*/walcrash2-4 (committed txn survives
    a crash modeled by truncating the `-wal` at the prior commit boundary; an
    uncommitted txn is discarded; integrity preserved).
  - `TestWalHookEngine` ⇄ e_walhook (the WAL hook fires per WAL commit and is
    silent in rollback/legacy mode).
  - `TestWalFaultHandlingEngine` ⇄ walfault/walfault2 (an I/O error during a WAL
    write is surfaced, not silently swallowed; previously-committed data stays
    recoverable).
- **Transpiler cannot emit these suites** (structural, matching the
  savepoint4/crash* precedent): `crashsql` fork+abort, the `test_syscall` /
  `faultsim` VFS fault injector, and the `sqlite3_wal_hook` C-API callback.

`skipTestFiles` reasons for all 7 packages were upgraded from
`"WAL/journal mode not implemented N-A"` to `"SUPERSEDED by native
frigolite_walrecovery_test.go ..."`.
