# P7.WAL-G7 — Multi-connection WAL subsystem (wal-index header + lock protocol + read-marks + snapshot API)

## Objective

Port `src/wal.c`'s multi-connection layer into frigolite's pager so two (or
more) `frigolite.Open()` connections on the same database file behave like two
SQLite connections on the same file in WAL mode:

1. a **shared wal-index** (`-shm`) with the exact `WalIndexHdr` /
   `WalCkptInfo` byte layout (double-buffered header, checksum, iVersion

   5 read marks) via `syscall.FcntlFlock` (inter-process) plus an

## Go idioms / platform notes

- **Locks**: `syscall.FcntlFlock(fd, syscall.F_SETLK, &syscall.Flock_t{
  Type: F_RDLCK|F_WRLCK|F_UNLCK, Whence: SEEK_SET, Start: int16(120+idx),
  Len: int64(n)})` — pure Go, no cgo. Shared = read lock, exclusive = write
  lock, exactly os_unix.c `unixShmLock` (`UNIX_SHM_BASE = (22+8)*4 = 120`).
- **macOS quirks (darwin dev box, darwin+linux CI)**:
  1. POSIX fcntl locks are **per-process**: two fds of the same process never
     conflict → intra-process arbitration MUST use the os_unix.c `aLock[]`
     shadow (refcounts under a mutex); flock is only the inter-process layer.
  2. Closing **any** fd to the shm file drops all of the process's POSIX
     locks on it → the registry owns exactly ONE shm fd per path, closed only
     at refcount zero.
  3. `FcntlFlock` can return `EINTR` → retry loop.
  4. Blocking `F_SETLKW` parks the OS thread → default build semantics
     (F_SETLK + busy-handler sleep loop, `walTryBeginRead`'s WAL_RETRY
     pattern, 100 retries → `SQLITE_PROTOCOL`); no F_SETLKW/SIGALRM.
- **Concurrency**: shared wal-index fields read cross-connection use
  `sync/atomic` loads (32-bit u32 fields, same as C's AtomicLoad on aReadMark/
  nBackfill); header page-0 buffer mutations happen only under the WRITER/
  RECOVER lock + the registry mutex.
- **No mmap**: wal-index pages are plain `[]byte` in the registry
  (`make([]byte, 32768)`), persisted to the `-shm` file with `WriteAt` after
  header/hash-table mutations so the on-disk `-shm` is meaningful (tests +
  cross-process). Torn-read protection within the process comes from locks;
  the double-buffer read protocol is implemented anyway for cross-process
  faithfulness.

## Architecture

### 1. Process-wide WALIndexRegistry (`internal/pager/walindex.go`)

```
WALIndexRegistry (package-level, like lockreg.Global but scoped to pager)
 └─ key: filepath.Clean(realPath) (already normalized at Open)
     └─ *WALIndex
        ├─ shmFd *os.File        // ONE fd for the path (lock ownership)
        ├─ pages [][]byte        // 32KiB wal-index pages (page 0 = header)
        ├─ aLock [8]int          // in-process shadow: 0 free, -1 exclusive, n>0 shared
        ├─ lockMu sync.Mutex     // guards aLock + page writes
        ├─ refs int              // connections attached
        └─ walPath string        // for recovery reads
```

- `openWal` (pager/wal.go) consults the registry: first connection creates/
  extends the shm to ≥32KiB; every connection on the same path gets the same
  `*WALIndex`. Each connection keeps its own `-wal` fd (like C's per-connection
  `pWalFd`) and its own `Wal` struct: `hdr` (cached WalIndexHdr), `readLock`
  (-1 none / 0..4 read-mark index), `writeLock`, `ckptLock`, `exclusiveMode`.
- Last detach closes the shm fd and (C parity: `sqlite3WalClose` with the
  last connection) attempts a passive checkpoint + deletes the `-wal`/`-shm`
  sidecars — preserving P7.WAL-C's close semantics for the single-connection
  case (see regression list).
- `dev+ino` keying (os_unix.c) noted as a refinement; path key suffices for
  the harness (distinct t.TempDir paths).

### 2. Wal-index header — EXACT byte offsets (verified in src/wal.c L306-475)

All fields **little-endian** (in-memory C struct; our targets are LE; the
`bigEndCksum` flag selects the WAL *frame* checksum byte order only, the
wal-index header checksum itself uses `walChecksumBytes(1, …)` = native = LE):

```
WalIndexHdr (48 bytes), copies at offsets 0 and 48:
   0: iVersion          u32  3007000 (WALINDEX_MAX_VERSION)
   4: unused            u32
   8: iChange           u32  (incremented each transaction)
  12: isInit            u8   (1 once initialized)
  13: bigEndCksum       u8
  14: szPage            u16  (1 == 65536; else page size)
  16: mxFrame           u32  (index of last valid frame)
  20: nPage             u32  (db size in pages)
  24: aFrameCksum[2]    u32  (of the last commit frame)
  32: aSalt[2]          u32  (copies of the WAL header salts)
  40: aCksum[2]         u32  (checksum over bytes [0:40])
WalCkptInfo (40 bytes) at offset 96:
  96: nBackfill         u32
 100: aReadMark[5]      u32  (READMARK_NOT_USED = 0xffffffff)
 120: aLock[8]          (lock bytes — never read/written as data)
 128: nBackfillAttempted u32
 132: notUsed0          u32
WALINDEX_HDR_SIZE = 136; WALINDEX_LOCK_OFFSET = 120; page 0 = 32768 bytes
```

- **Write protocol** (`walIndexWriteHdr`): set `isInit=1`, `iVersion=3007000`,
  recompute `aCksum` over `[0:40]`, write copy at **48 first**, barrier, then
  copy at 0.
- **Read protocol** (`walIndexTryHdr`): read copy 0, barrier, read copy 1;
  mismatch → dirty read → retry (under WRITER lock; still bad → recover).
  Verify checksum + `isInit`; `iVersion != 3007000` → CANTOPEN.
- **Hash tables** (frames 4063+ live on shm pages 1..N): `HASHTABLE_NPAGE`
  4096, `HASHTABLE_NPAGE_ONE` 4062, `HASHTABLE_NSLOT` 8192,
  `HASHTABLE_HASH_1` 383; `walHash(pgno) = (pgno*383) & 8191`, linear probe
  `walNextHash = (i+1) & 8191`; slots are u16 (`ht_slot`) storing
  `iFrame - iZero`; `aPgno[]` (u32 per frame) starts at offset 136 on page 0.
  Port `walIndexAppend` / `walIndexFind` / `walCleanupHash` / `walFramePage`.

### 3. Lock protocol (`internal/pager/wallocks.go`)

shm byte = `120 + idx` on the `-shm` fd; shadow `aLock[]` mirrored:

| idx | byte | name | usage |
|---|---|---|---|
| 0 | 120 | WAL_WRITE_LOCK | one writer at a time; exclusive |
| 1 | 121 | WAL_CKPT_LOCK | checkpointer + `snapshot_recover`/`snapshot_check` shared |
| 2 | 122 | WAL_RECOVER_LOCK | recovery in progress (shared-held signals BUSY_RECOVERY) |
| 3..7 | 123..127 | WAL_READ_LOCK(0..4) | shared-held by readers; exclusive to change aReadMark / backfill |

- **Recovery lock dance** (`walIndexRecover` port, wal.c L1384): caller holds
  WRITER; take exclusive on `WAL_ALL_BUT_WRITE + ckptLock .. WAL_READ_LOCK(0)-1`
  (bytes 121..122); rebuild wal-index from the `-wal` (validate header magic/
  page-size/checksum/version; walk frames with `walDecodeFrame` salt+cksum
  rules; mxFrame/nPage at commit records); write header; reset ckpt info
  (`nBackfill=0`, `nBackfillAttempted=mxFrame`, `aReadMark[0]=0`,
  `aReadMark[1]=mxFrame` if mxFrame>0 else marks 1..4 = READMARK_NOT_USED,
  each set under a transient exclusive READ_LOCK(i)); unlock. Block on any
  lock for ≤100 retry rounds → `SQLITE_PROTOCOL` ("locking protocol").
- **Writer**: exclusive WRITER (busy handler on BUSY); verify shared header
  unchanged vs own read snapshot else `SQLITE_BUSY_SNAPSHOT` ("database is
  locked", extended code, walprotocol2-2.2/2.3); append frames with the
  existing checksum chain; `walIndexAppend` each frame; bump `mxFrame`,
  `nPage`, `aFrameCksum`, `iChange++` via the double-buffered header write;
  fire `walHook`.
- **WAL reset** (`walRestartLog`/`walRestartHdr` port, wal.c L2146/3852): at
  commit when `nBackfill == mxFrame` and the writer holds READ_LOCK(0) with
  no other readers: exclusive READ_LOCK(1..4); `nCkpt++`, `mxFrame=0`,
  salt1 = old salt1 + 1, salt2 randomized, `nBackfill=0`,
  `nBackfillAttempted=0`, `aReadMark[1]=0`, marks 2..4 = READMARK_NOT_USED;
  new frames overwrite from frame 1.
- **Checkpoint** (`walCheckpoint` PASS1/PASS2 port, wal.c L2193):
  - PASS1: `mxSafeFrame = mxFrame`; for i=1..4 where `aReadMark[i] <
    mxSafeFrame` try exclusive READ_LOCK(i); BUSY → `mxSafeFrame =
    aReadMark[i]` (PASSIVE never invokes the busy handler); exclusive
    READ_LOCK(0); `nBackfillAttempted = mxSafeFrame`; iterate frames
    page-sorted (port `walIteratorInit/Next`); backfill `(nBackfill,
    mxSafeFrame]` into the main file; truncate main db to `nPage*pageSize`
    when `mxSafeFrame == header.mxFrame`; `nBackfill = mxSafeFrame`; unlock.
    BUSY readers → report, not error.
  - PASS2 (`eMode != PASSIVE`): `nBackfill < mxFrame` → `SQLITE_BUSY`;
    `eMode >= RESTART`: exclusive READ_LOCK(1..4) (busy handler);
    TRUNCATE: `walRestartHdr` + truncate `-wal` to 0 bytes.
  - `PRAGMA wal_checkpoint` result triple `(busy, nLog, nCkpt)` —
    walprotocol-2.1 `{0 5 5}`, walrestart-1.2 `{0 45 0}`.

### 4. Reader read-mark snapshot protocol (`walTryBeginRead` port, wal.c L3000)

Per read transaction (autocommit statement or explicit BEGIN; engine hook at
the point where `CheckExternalFile` runs today, `internal/exec/external_checks.go:85`):

1. `walIndexReadHdr`: try-lockless header read; bad → WRITER lock + re-read →
   still bad → `walIndexRecover` (`*pChanged` → drop page cache).
2. `nBackfill == mxFrame` (WAL fully backfilled, empty, or snapshot_get case
   excluded) → shared READ_LOCK(0); verify header unchanged (else unlock +
   retry); read from the **main file only**.
3. Else pick `aReadMark[i]` (i=1..4), largest ≤ mxFrame (≤ snapshot's mxFrame
   when opening a snapshot); if max < mxFrame, grab an exclusive READ_LOCK(i),
   bump the mark to mxFrame, unlock; shared-lock READ_LOCK(mxI); verify mark
   and header unchanged (else retry); **reader pins mxFrame = that mark**
   until COMMIT/ROLLBACK (unlock shared).
4. Retries: BUSY → sleep (busy handler / timeout) → retry; >100 →
   `SQLITE_PROTOCOL`.
5. **Page read** (`sqlite3WalFindFrame` port): hash-lookup pgno in the shared
   wal-index; take the largest frame ≤ reader mxFrame and > `minFrame`
   (= nBackfill observed at lock time); read frame data from the `-wal` fd at
   `walFrameOffset`; else the main file. `Pager.ReadPage` gains this WAL path
   (replacing the "replay committed frames into p.pages" model for reads —
   the replay stays for the single-connection fast path only where it is
   observationally identical, or is removed wholesale if simpler; both
   outcomes keep `frigolite_walrecovery_test.go` green).
6. **Cross-connection cache invalidation**: header changed since the
   connection's cached hdr (`pChanged`) → `InvalidateCache`-equivalent reset
   (pager.c `pager_reset`) + schema reload when `iChange` moved — wired into
   the engine's per-statement external-mod check, which in WAL mode switches
   from main-file stamp to wal-index header stamp.

### 5. Snapshot API surface (`frigolite.go`, P5.CAPI conventions)

```go
// sqlite3_snapshot C-API parity (SQLITE_ENABLE_SNAPSHOT is on in modern builds).
func (db *DB) SnapshotGet(schema string) (*Snapshot, error)         // copy of connection hdr; errors: not WAL, autocommit on, write txn open, empty WAL (aFrameCksum==0)
func (db *DB) SnapshotGetBlob(schema string) ([]byte, error)        // 48-byte LE blob (snapshot2)
func (db *DB) SnapshotOpen(schema string, snap *Snapshot) error     // next read txn anchored at snap.mxFrame; SQLITE_ERROR_SNAPSHOT if outdated
func (db *DB) SnapshotOpenBlob(schema string, blob []byte) error
func SnapshotCmp(a, b *Snapshot) int                                // aSalt[0], then mxFrame
func SnapshotCmpBlob(a, b []byte) (int, error)
func (db *DB) SnapshotRecover(schema string) error                  // walIndexRecover under CKPT+RECOVER; errors outside WAL/txns
```

- `Snapshot` wraps the 48-byte `WalIndexHdr` image (salt + mxFrame are what
  `walTryBeginRead` and `SnapshotCheck` consult: shared CKPT_LOCK held for
  the check; salt mismatch or `mxFrame < nBackfillAttempted` →
  `SQLITE_ERROR_SNAPSHOT`, "snapshot is out of date"? — error TEXT taken
  from the oracle at implementation time, code pinned by native tests).
- Reader-anchored read transactions use the `pSnapshot` branch of the
  read-mark selection (mxFrame capped at the snapshot's).

## Risks

- **R1 — lock-semantics mismatch (biggest)**: POSIX fcntl locks are
  per-process, so a flock-only design silently gives every same-process
  connection every lock (all tests "pass", nothing is synchronized). The
  `aLock[]` shadow is therefore load-bearing, not optional; it must be
  acquired/released atomically with the flock (same mutex) or a crash can
  strand divergent state between shadow and kernel. Lock ordering follows
  os_unix.c's list (RECOVER > CKPT > WRITE > READ); a blocking acquisition
  must never be attempted while holding a later lock (debug assert parity).
- **R2 — race conditions / torn header reads**: double-buffer write
  (copy1 → barrier → copy0) + double-read + checksum must be ported
  verbatim; Go atomics for `aReadMark`/`nBackfill`/`mxFrame` reads; -race in
  every slice's verify. Deadlock candidates: recovery (needs all locks) vs
  concurrent readers; checkpoint PASS2's READ_LOCK(1..4) grab.
- **R3 — macOS vs Linux flock differences**: close-drops-all-locks (registry
  owns one fd), EINTR retries. `syscall.Flock_t` field types are identical on
  darwin/linux (Start/Len int64, Type/Whence int16 — verified against Go
  1.27 ztypes_darwin_arm64.go), so one construction compiles everywhere;
  darwin is the dev box, CI covers linux; both pinned by native tests.
- **R4 — pager cache invalidation across connections**: a reader must see
  another connection's commits (walprotocol 2.3); the per-statement header
  stamp check must not thrash the cache for single-connection WAL (fast path:
  stamp unchanged → no reset); interplay with `CheckExternalFile`
  (checkpointed main-file growth) needs both signals composed, not replaced
  blindly. Schema reload on iChange (cookie) must not fight the existing
  external-mod schema reload.
- **R5 — P7.WAL-C regressions**: Open/recovery/CheckpointMode/hook/fault
  behavior is pinned by `frigolite_walrecovery_test.go` + `wal_test.go` +
  walconformance fixtures + incrvacuum2 `-wal` size assertions; the
  single-connection registry fast path must produce byte-identical `-wal`
  output (checksum chain unchanged) — verified per slice, not at the end.
- **R6 — full-suite drift**: WAL-mode tests across the 1002-file harness
  (incrvacuum*, walcrash, walhook, journalmode*) exercise Open/Close/commit
  paths this goal touches; per-slice `tools/status --check` gates catches
  flips at the slice that caused them.
