### Failure analysis (incrvacuum3, HEAD state)

incrvacuum3 1.1.2 (DELETE FROM t1 WHERE rowid%8, av=2, page_size=1024,
cache_size=5): integrity_check → "trunk 6 leafCount=33607168 exceeds
maxLeaves=248". Later steps: "Freelist: size is 96 but should be 46".

Root cause class: the pager maintains THREE parallel freelist mechanisms
that are not in the C source and diverge from the on-disk chain:

1. `p.freePages` Go-map set (AllocatePage pops from it first).
2. `p.trunkPages` / `p.leafToTrunk` maps + `pickNextFreePageLocked`
   chain-order picker + `popFromFreePagesChainLocked` (sub-case (b)
   leaf-promotion rewrite that no C code path performs on pop).
3. A legacy AllocatePage on-disk branch that CLEARS every leaf and
   consumes the whole trunk head, dropping the rest of the chain.

C SQLite (btree.c) has NO in-memory freelist state: the on-disk chain
(page1[32] first trunk, page1[36] count, trunk pages) is the single
source of truth. Per working directive: the engine MUST follow SQLite.

Confirmed concrete divergences vs src/btree.c:

| # | site | engine | C (btree.c) |
|---|------|--------|-------------|
| D1 | FreePage leaf cap | `pageSize/4 - 10` | `usableSize/4 - 8` (freePage2: nLeaf < usable/4-8 → leaf-add) |
| D2 | FreePage idempotence branch | re-add guard keyed on trunkPages/leafToTrunk maps, count++ only | none — freePage2 always chains; C callers free each page once |
| D3 | AllocatePage pop | pickNextFreePageLocked (chain-walk, ptrmap skip, fallbacks) + popFromFreePagesChainLocked leaf-promotion | allocateBtreePage: k=trunk[4]; k==0&&!searchList → take TRUNK itself, header[32]=trunk[0:4]; k>0 → take leaf[closest], copy LAST leaf into slot (`aData[8+closest*4] = aData[4+k*4]`), trunk[4]=k-1 |
| D4 | AllocatePage legacy on-disk branch | zeroes every leaf, consumes head trunk, drops chain tail | absent in C |
| D5 | AllocatePage append-at-end | own logic | nPage++; skip PENDING_BYTE_PAGE; if av && new page is ptrmap page → allocate TWO (ptrmap + user); header[28]=nPage (allocateBtreePage else-branch) |
| D6 | TakePageFromFreelist | popFromFreePagesChainLocked | allocateBtreePage(BTALLOC_EXACT, nearby): searchList iff ptrmapGet(nearby)==FREEPAGE; walks chain; trunk-hit → first leaf becomes new trunk (k-1 leaves, same next); leaf-hit → copy-last-into-slot |
| D7 | IsPageOnFreelist | p.freePages map | ptrmapGet == PTRMAP_FREEPAGE (incrVacuumStep:6780 uses ptrmap) |
| D8 | AllocatePageLE | pickNextFreePageLocked + pop | allocateBtreePage(BTALLOC_LE, nearby=nFin): searchList walk; first leaf ≤ nearby; trunk ≤ nearby allocates trunk |

- **a433c318 (incrvacuum2 4.1 btree divider)** — SQLite's leafData

  `PRAGMA wal_checkpoint` with no argument defaults to
