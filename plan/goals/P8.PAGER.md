### Batch 1 plan (root causes + exact changes)

1. **stmtrand() engine function** (ext/misc/stmtrand.c port):
   - Discriminator: LCG validated against the TCL literal sequences
     (seed 0 → `4 1 8 3 6 1 4 9 2 1 2 1 0 1 8 1 4 7 6 1 8 7 0 3 0 9 4 5 9 9`,
     seed 1 → `3 8 9 4 7 2 3 8 5 2 7 0 3 0 7 2 5 6 1 8 5 6 7 8 7 2 9 6 8 0`)
     — Go uint32 arithmetic matches exactly (x=(x>>1)^((1+~(x&1))&0xd0000001);
     y=y*1103515245+12345; result=(x^y)&0x7fffffff).
   - Auxdata semantics are observable: 1.4 `stmtrand(x)` (seed=first row's x=1)
     produces the SAME sequence as 1.3 `stmtrand(1)` → one LCG per STATEMENT,
     seeded by the FIRST call's argument; later args ignored; reset per
     statement.
   - Changes: `internal/execexpr/types.go` (Evaluator.stmtAux +
     AuxData/SetAuxData/ResetStatementAux), `expression_eval.go`
     evalEngineFunc `case "STMTRAND"`, `internal/exec/engine_core.go` Exec
     reset next to counterVal (outermost execDepth only — nested trigger
     statements share the outer aux, a documented approximation),
     `internal/function/function.go` registration (0-1 args, fresh-state
     fallback ScalarFn for contexts without statement scope).
2. **cteMainVerbIsQuery** (tools/tcl2go/sqlhelpers.go): any CTE with a column
   list `WITH name(cols) AS (...) SELECT` mis-classifies as non-query
   (the name's `()` closes depth→0 and the tail starts with "AS" → false),
   so do_execsql_test drops the result comparison (stmtrand 1.1-1.4). Rewrite
   as a structured scan: name → optional balanced column-list → AS → balanced
   body → [`,` more CTEs] → main verb SELECT/VALUES ⇒ query.
3. **`read $fd <expr>` count** (processset.go ~714 + processset_part2.go ~209):
   `set data [read $fd [expr 20*1024]]` split the expr across whitespace
   Fields and emitted `tclReadFileWithLen(fd, [expr)` → Go syntax error
   (memdb1 436). Reconstruct the bracket-balanced count text; transpile-fold
   plain literal exprs, else emit `toInt(<runtimeExprValue>)`.
4. **pending byte** (pager1 build + faithful movement):
   - gen.go: extend the shadow-var pre-declaration to sources containing
     `sqlite3_test_control_pending_byte` (pager1 assigns the shadow via that
     command but never mentions the global).
   - processSqlite3TestControlPendingByte: emit `db.SetPendingByteMain(n)`
     (the engine seam exists, engine.go:408) alongside the shadow var;
     `$var` args emit runtime dispatch (current code errors on ParseInt).
   - `set pending_prev [sqlite3_test_control_pending_byte 0x1000000]` must
     capture the PREVIOUS byte (test/42.x restores it) — make
     Engine.SetPendingByteMain return the previous offset (additive), DB
     wrapper likewise, transpile the set-capture form.
   - Engine read-side behavior for a pending-byte page inside an existing db
     (pager1 42.1 expects "database disk image is malformed") — mechanism
     under investigation in the C source; decide AFTER the package builds.
