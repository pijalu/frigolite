## T-LOG (2026-09-07, engine locking + rebind semantics — 3/4 packages green)

**exclusive ✅**: cross-connection locking_mode=EXCLUSIVE now holds a
persistent SHARED lock (internal/lockreg PersistentShared +
Engine.clearPersistentShared, wired lazily in CrossConnLockError on first
access when the connection's locking mode is exclusive):
- an autocommit write by another connection fails immediately
  ("database is locked", exclusive-2.5 — the EXCLUSIVE upgrade cannot be
  granted);
- a write inside an explicit transaction acquires RESERVED and fails at
  COMMIT (commitLockError checks PersistentSharedByOther — 2.6/2.7),
  leaving the transaction open so the subsequent ROLLBACK succeeds (2.8).
Pure-Go pre-test confirmed the active-transaction case already worked;
the gap was the never-released lock after locking_mode=EXCLUSIVE.

**Transpiler rebind semantics (exclusive ✅ / general correctness)**: TCL's
"sqlite3 NAME FILE" closes the connection previously bound to NAME. The
generated Go leaked it open, so the leaked writer's open transaction
blocked hot-journal playback on the recreated file (exclusive-6.5).
tclConnRegister now closes the previous handle on rebind (guarded by
IsClosed — an already-explicitly-closed handle is not re-closed).
