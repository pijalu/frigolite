**T0 census**: all 7 packages were vacuous stubs ("deep-engine applicable
gap DEFERRED"); un-skipped (vacuum, vacuum-into, vacuum2..vacuum6) and
regenerated. vacuum4/vacuum5/vacuum6 pass without changes. Baseline
categorization of the 4 failing packages:

1. **Engine: VACUUM is a no-op** (engine_tail.go default case). Needed per
   src/vacuum.c: (a) "cannot VACUUM from within a transaction"; (b) VACUUM
   INTO 'file' (exclusive new-file creation); (c) the rebuild itself —
   compaction is REQUIRED (vacuum-1.3 asserts file-size shrink;
   vacuum3-1.4.x asserts pending page_size applied). A page-verbatim backup
   does NOT compact; SQLite builds the vacuum_db LOGICALLY (re-creates
   tables/indexes from sqlite_schema.sql with statements redirected into
   the vacuum db, INSERT INTO vac.tbl SELECT * FROM main.tbl per table,
   copies view/trigger/vtab schema rows directly, preserves meta values
   with a schema-cookie bump) and then sqlite3BtreeCopyFile (backup) the
   compact image back over main.
   Implementation plan (frigolite_vacuum.go + parser):
   - parser: capture the INTO target (rule 251) into VacuumStmt.Into [DONE].
   - VACUUM INTO / plain VACUUM via a logical rebuild:
     ATTACH an in-memory vacuum_db in the same engine, re-create the
     schema there (schema-qualified rewrite of the stored CREATE text),
     INSERT..SELECT per table, copy view/trigger/rootpage-0 schema rows,
     preserve user_version/application_id, bump the schema cookie, then
     backup vacuum_db → main (existing Backup machinery) and DETACH.
   - Transaction guard: engine.InTransaction() check [DONE].
2. **Transpiler: cksum proc** (vacuum, vacuum2): "proc cksum db" style
   table checksums need the same inlining treatment as t1sig
   (tableSigProcInfo precedent).
3. **Transpiler: expected-value exprs** (vacuum2-2.1/2.2):
   `do_test X { body } {[hexio_get_int [hexio_read test.db 24 4]]+3}` —
   the EXPECTED argument contains a bracketed expression; the comparison
   must evaluate it at runtime (tclExprWith/tclHexioReadInt composition).
4. **Engine: page_size on VACUUM** (vacuum3): VACUUM applies a pending
   PRAGMA page_size change to the rebuilt database.
5. vacuum-into 7xx: PRAGMA schema_version/counter introspection shapes.
