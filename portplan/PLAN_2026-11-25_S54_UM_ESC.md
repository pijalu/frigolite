# Plan — S54 slice 2: fts4umlaut Unicode escapes (2026-11-25)

## Problem

`fts4umlaut` has 12 failing leaves (`1.4.3` onward), all reporting `0`
instead of `1`. The failing SQL contains literal `u1ed9`, `u006f`, `u0302`
text; SQLite's TCL source (`../sqlite/test/fts4umlaut.test`) uses double-quoted
`\uXXXX` escapes inside `$q`. The converter emitted the letters after the
backslash but dropped the backslash itself, so the harness never sent the
Unicode characters the oracle sends.

## Method

1. Write a pure-Go pin using `frigolite.Open/Exec/Query` with real Go Unicode
   strings for the same 1.1–1.7 assertions. If it passes, the engine is not
   at fault and the converter/fixture is the unit.
2. Localize the TCL string-escape handling in `tools/tcl2go/`; fix `\uXXXX`
   decoding for double-quoted TCL words, regenerate `testdata/fts4umlaut.json`,
   and verify the regenerated SQL contains actual Unicode characters.
3. Run focused `fts4umlaut`, raw-byte diff against the full baseline, quality,
   and a detached full gate (NEW must stay 0).

## Exact files

- New `frigolite_fts4umlaut_t16_pin_test.go`.
- Converter file(s) found by step 2; `testdata/fts4umlaut.json` regenerated.
- Plan/handoff/TODO/lessons updated after verification.

## Risks / non-goals

- Raw-byte leaf-set diffs only; no count/line greps.
